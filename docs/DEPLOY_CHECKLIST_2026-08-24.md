## ٢. اتأكد بنفسك (٣ دقايق)

بعد ما الرفعة تخلص وتعمل `Ctrl+F5`:

- [ ] **بيعة حقيقية تعدّي** — أهم اختبار. لو وقعت، رجّع النسخة القديمة من Vercel وابعتلي
- [ ] **صفحة الأصناف** — المفروض تشوف البحث والبضاعة أول ما تفتح، وزرار واحد فوق
- [ ] **افتح صنف وعدّل اسمه بس واحفظ** — ارجع بصّ على تكلفته، المفروض ما اتغيرتش
- [ ] **الإعدادات** — تلات سطور مطوية، وقايمة نوع النشاط فيها ٤٨ اختيار
- [ ] **الرئيسية** — قيمة المخزون بتوري رقم حقيقي مش صفر

## ٣. وبعدين بس، اقفل الباب القديم

```
database/migrations/076_close_sell_line_after_deploy.sql
```

شغّله من Supabase SQL Editor **بعد** ما البيعة تعدّي في الخطوة ٢.

هو بيمنع `sell_line` عن المتصفح. طول ما هي متاحة، حد يقدر ينادي:

```js
rpc('sell_line', { p_unit_price: 1, p_total: 1, ... })
```

ويبيع صنف بـ٢٣٠ بجنيه. `record_sale` قفلت الباب اللي الواجهة
بتستعمله، و٠٧٦ بيقفل اللي جنبه.

لو حصلت مشكلة بعد ما تشغّله وعايز ترجع بسرعة:

```sql
grant execute on function
  public.sell_line(uuid, uuid, numeric, uuid, numeric, numeric)
  to authenticated;
```

## ٤. حاجة واحدة مش في الكود

**حماية كلمات السر المسرّبة مقفولة في Supabase.** خمس ثواني:

`Supabase Dashboard → Authentication → Policies → Leaked password protection`

بيخلي Supabase يرفض أي كلمة سر ظهرت في تسريب معروف.

   للاستغلال للمكسب، بس صف بيانات غلط ينفع يتكتب. تريجر صغير يحلّها.

   مصروف وهمي يغطّي عجز في الدرج. ضبط إداري مش ثغرة، بس فكّر فيها.

٣. الإيصال المطبوع لسه بيتحسب في المتصفح. الإجمالي المسجّل بقى من
   القاعدة، فلو سعر اتغير والعربية مفتوحة، الورقة والفاتورة ممكن
   يختلفوا.
