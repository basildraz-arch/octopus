# الرفع على الموقع

المشروع على **Vercel** (مشروع `octopus`، تيم `octopus-team1`) والكود على
**GitHub** (`basildraz-arch/octopus`، فرع `master`).

## اللينكات — واحد بس هو اللي تديه للناس

| اللينك | إيه هو |
|---|---|
| **`octopus-fawn-three.vercel.app`** | **الموقع.** ثابت، مفتوح للناس. ده اللي تبعته |
| `octopus-octopus-team1.vercel.app` | alias داخلي للتيم، Vercel بيقفله على غير المسجّلين. ما تستعملهوش |
| `octopus-<حروف>-octopus-team1.vercel.app` | لينك رفعة واحدة، بيتغير كل مرة. ما تحفظهوش |

> **⚠️ أهم حاجة في الملف ده: إن النسخة اتبنت مش معناه إن الناس شافتها.**
>
> الـ`git push` بيبني نسخة، و`npx vercel --prod` بيبني نسخة كمان — الاتنين
> بيقولوا `● Ready`، و**الدومين الأساسي ممكن يفضل على نسخة قديمة**.
>
> ده حصل فعلًا: `octopus-fawn-three.vercel.app` فضل ٦ أيام على نسخة ١٥
> أغسطس بينما أربع رفعات نزلت فوقيها. الموقع كان شغال، بس بالكود القديم.

## الخطوات بالترتيب

افتح PowerShell في مجلد المشروع:

```powershell
cd C:\Users\LOGO\Desktop\octopus
```

### ١ — اتأكد إن الكود سليم

```powershell
npm run build 2>&1 | Tee-Object build.log
```

**ما تكمّلش غير لو عدّى** (`✓ Compiled successfully`). الساندبوكس بتاعي
مش بينزّل حزم فما بقدرش أعمل الـbuild بنفسي — أي خطأ أنواع بيظهر هنا بس.
لو وقع، الخطأ متسجّل في `build.log` وأنا بقدر أقراه من مكاني.

### ٢ — احفظ الكود على GitHub

```powershell
git add .
git commit -m "server-computed subscription price, grouped master page"
git push origin master
```

### ٣ — نزّله على الموقع

```powershell
npx vercel --prod
```

لو طلبت `Error: Not authorized` نفّذ `npx vercel login` الأول (هيديك كود
تدخله في المتصفح)، وبعدها كرّر الأمر.

**احفظ لينك النسخة اللي هيطلع** في سطر `Production` — هتحتاجه في الخطوة
اللي بعدها.

### ٤ — ⚠️ اتأكد إن الدومين اتحرك (ما تعديهاش)

```powershell
npx vercel inspect https://octopus-fawn-three.vercel.app
```

بصّ على سطر **`created`**. لازم يكون النسخة اللي لسه رافعها دلوقتي.
لو طلع تاريخ قديم، يبقى الدومين لسه على النسخة القديمة والناس شايفة
القديم — رقّي النسخة الجديدة:

```powershell
npx vercel alias set <لينك-النسخة-من-الخطوة-٣> octopus-fawn-three.vercel.app
```

**أو من المتصفح (أنضف وبيظبط كل الدومينات مرة واحدة):**

`vercel.com` → مشروع `octopus` → **Deployments** → أحدث نسخة → `⋯` →
**Promote to Production**

وبعدها افتح الموقع بـ`Ctrl+F5` — من غير كده المتصفح ممكن يوريك المحفوظ
عنده.

## سؤال مفتوح: ليه الدومين مش بيترقّى لوحده؟

المشروع **مربوط بـGitHub فعلًا** (فيه alias بصيغة
`octopus-git-master-octopus-team1.vercel.app`، وVercel بيعملها للنسخ
الجاية من push بس). المفروض الـpush يبني ويرقّي تلقائيًا — وده مش بيحصل.

**السبب لسه مش معروف.** عشان نعرفه، محتاجين نبص على:

- `vercel.com` → `octopus` → **Settings → Git** — فيه repo مربوط ولا لأ؟
  والـProduction Branch مضبوط على `master`؟
- `vercel.com` → `octopus` → **Settings → Domains** — مكتوب إيه جنب
  `octopus-fawn-three.vercel.app`؟ لو جنبه اسم فرع أو نسخة معينة، يبقى
  مثبّت يدويًا ولازم يتفك.

لحد ما ده يتحل، **الخطوة ٤ إجبارية بعد كل رفع.**

## قبل ما ترفع: راجع الـEnvironment Variables على Vercel

ملف `.env.local` **مش بيترفع** (مقفول في `.gitignore`)، فأي مفتاح لازم
يكون متسجّل في Vercel نفسه. افتح:

**Vercel → octopus → Settings → Environment Variables**

واتأكد إن دول موجودين في **Production**:

| المفتاح | لو ناقص هيحصل إيه |
|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | الموقع مش هيفتح خالص |
| `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` | الموقع مش هيفتح خالص |
| `SUPABASE_SERVICE_ROLE_KEY` | **كل صفحات Master تقع** — الموافقات، الأكواد، الأسعار، حسابات الموظفين |
| `GEMINI_API_KEY` | الأخطبوط الذكي يرمي خطأ |
| `SIGNUP_INVITE_CODE` | محدش يقدر يسجّل حساب جديد |
| `PAYMOB_*` (4 مفاتيح) | الدفع أونلاين مش هيشتغل |

راجعناهم مع بعض وكانوا كلهم موجودين.

`SUBSCRIPTION_PRICE_EGP` **بقى مش مستخدم** — السعر دلوقتي بيتحسب على
السيرفر لكل محل من قوايمه (`lib/monthlyDue.ts`). سيبه أو امسحه، مش فارقة.

## بعد الرفع: خمس دقايق تتأكد

١. افتح الموقع وسجّل دخول بحسابك.

٢. `/master` — لازم تشوف خمس مجموعات مطويّة (البيزنسات مفتوحة).

٣. `/settings` — تلات مجموعات، وجوه "محلك" زرار **تصدير بياناتك**. نزّل
   ملف الأصناف واتأكد إن العربي طالع صح في إكسل.

٤. **`/sales` — اعمل بيعة واحدة لصنف عنده مخزون، وبعدين افتح `/items`
   واتأكد إن الكمية نقصت فعلًا.**

٥. `/subscribe` — لازم يظهر مبلغ محسوب من قوايمك (مش رقم ثابت)، ولو
   عندك إحالات شغالة يظهر سطر الخصم.

٦. اسأل الأخطبوط سؤال بسيط.

**الخطوة رقم ٤ هي الأهم وما اتعملتش لحد دلوقتي.** قاعدة البيانات اتغيرت
كتير (سحب المخزون بقى بيمرّ على `draw_stock_fifo`)، والبيعة دي هي اللي
بتثبت إن الكود الجديد والقاعدة الجديدة ماشيين مع بعض.
